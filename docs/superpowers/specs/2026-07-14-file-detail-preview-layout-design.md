# 文件详情预览与无滚动布局设计

## 目标

改造云盘右侧文件详情栏，使文件点击后能够展示有效预览，并在当前应用窗口内完整显示预览、文件属性和全部操作按钮，不再出现纵向滚动条。

## 范围

- 图片文件：直接展示图片内容。
- 视频文件：展示由现有缩略图服务提取的视频第一帧。
- 其他文件：继续展示对应的 SF Symbol 文件类型图标。
- 文件详情：展示文件名、大小、类型、上传时间和直接父目录名称。
- 操作区域：保持在线播放、立即下载、重命名、删除文件等现有功能入口。
- 不修改文件详情请求帧、上传下载帧、在线播放协议和缩略图存储规则。

## 布局设计

详情栏移除 `ScrollView`，使用固定的垂直布局和自适应尺寸：

1. 顶部标题栏保持固定高度。
2. 预览区域根据可用高度在紧凑尺寸和常规尺寸之间调整。
3. 文件名限制为最多两行，采用中间省略；鼠标悬停时显示完整文件名。
4. 属性区域使用四行紧凑布局，长文本中间省略；鼠标悬停时显示完整内容。
5. 存储目录仅显示文件的直接父目录名称，不显示完整物理路径。
6. 操作按钮采用两列网格，视频文件显示四个按钮；非视频文件显示下载、重命名、删除按钮。
7. 缩小详情栏上下留白和控件间距，确保所有按钮始终处于可视范围。

## 预览数据流

点击文件时并行执行两项工作：

1. 通过现有 `DirectoryService.fetchFileDetail` 获取完整文件详情。
2. 将列表中的 `DirectoryItem` 或详情转换后的 `DirectoryItem` 交给 `FileThumbnailService`：
   - 图片调用清晰预览加载能力，优先读取内存和磁盘缓存，未命中时从服务端加载。
   - 视频调用缩略图能力，复用现有 HTTP Range 抽帧和缓存逻辑。
   - 非图片、非视频不发起媒体网络请求。

切换选中文件时取消旧预览任务，并用文件 ID 校验异步结果，避免旧文件预览覆盖当前详情。

## 状态与错误处理

- 加载中：预览区域显示小型进度指示器和文件类型占位图标。
- 加载成功：按比例展示图片或视频首帧，不拉伸、不撑高详情栏。
- 加载失败：回退到文件类型图标，不影响属性和操作按钮显示。
- 文件详情请求失败：保留当前列表中已有的基础文件信息作为降级展示，并结束加载状态。
- 文件切换或详情栏销毁：取消旧预览任务。

## 响应式约束

- 详情栏宽度继续沿用现有 `273...468` 点范围。
- 常规高度使用较大的预览图；较低窗口高度自动降低预览尺寸、间距和按钮高度。
- 不通过隐藏按钮解决空间不足，也不重新引入滚动容器。
- 超长文本只影响自身显示，不允许挤压预览区或操作区。

## 验收标准

1. 点击图片文件，右侧显示实际图片。
2. 点击视频文件，右侧显示视频第一帧。
3. 图片或视频预览失败时显示类型图标，详情仍可操作。
4. 文件名和目录过长时不撑高布局，悬停可查看全文。
5. 在线播放、下载、重命名、删除按钮全部可见且功能入口保持不变。
6. 详情栏不存在纵向滚动条。
7. 快速切换多个文件时不会显示错位的旧预览。
