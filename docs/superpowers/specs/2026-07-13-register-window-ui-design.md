# chat-storage 两步注册窗口 UI 设计

## 1. 目标

注册页面采用已确认的方案 C：完全复用登录页的固定双栏外壳，将注册表单拆分为“基础资料”和“安全设置”两个步骤，在 `720 x 456` 窗口内保持登录与注册的品牌、尺寸、配色和交互语言一致。

本次只调整 SwiftUI 页面结构与表单步骤，不修改注册帧类型、认证服务、输入校验规则、头像压缩方式或服务端接口。

## 2. 页面结构

### 2.1 左侧品牌区

左侧占窗口宽度 40%，与 `LoginView` 保持相同内容和视觉：

- “D”品牌标记和“毒药网盘”名称。
- “让聊天与文件，始终触手可及。”主文案。
- 聊天和私人云盘说明。
- 底部服务器连接状态。
- 相同的深色背景、圆环装饰、内边距和字号。

注册页不再把头像选择放在左侧，避免登录和注册切换时品牌区域发生明显跳变。

### 2.2 右侧两步表单

右侧表单固定宽度 310pt，顶部显示步骤文字和双段进度条。

第一步“基础资料”包含：

1. 头像选择。
2. 账号。
3. 邮箱。
4. 固定高度错误区域。
5. “下一步”主按钮。

第二步“安全设置”包含：

1. 密码。
2. 确认密码。
3. 固定高度错误区域。
4. “上一步”次按钮。
5. “创建账号”主按钮。

两步底部均提供“已有账号？返回登录”。

## 3. 交互规则

- 第一步点击“下一步”时校验账号和邮箱；校验失败停留当前步骤并聚焦错误字段。
- 第一步校验成功后进入第二步并聚焦密码。
- 第二步点击“上一步”时保留所有已填写内容和头像。
- 第二步点击“创建账号”时继续执行原有完整校验和注册请求。
- 账号输入回车后聚焦邮箱，邮箱输入回车后进入第二步。
- 密码输入回车后聚焦确认密码，确认密码输入回车后提交注册。
- 密码与确认密码保留显隐按钮。
- 注册中锁定步骤切换、返回登录、头像选择和输入控件。
- 注册失败停留第二步显示错误；注册成功返回登录页。

## 4. 视觉规范

- 输入框高度、边框、聚焦描边、阴影和内边距与登录页一致，统一为 42pt 高。
- 主按钮与登录按钮一致，使用 Telegram 蓝色、42pt 高和相同圆角。
- 次按钮使用系统背景和描边，不与主操作争夺视觉层级。
- 步骤进度条使用两个固定宽度轨道，当前及已完成步骤显示强调色。
- 头像选择使用紧凑横向控件，头像为 52pt 圆形，不改变表单宽度。
- 错误区域始终预留 28pt，避免错误文本造成按钮跳动。
- 页面不使用滚动条，所有状态均必须完整适配固定窗口。

## 6. 验收标准

- 登录页与注册页左侧品牌区视觉一致。
- 两步注册流程在 `720 x 456` 窗口内无裁切和重叠。
- 第一步只负责基础资料，第二步只负责密码安全设置。
- 前后切换不会丢失输入和头像。
- 原有注册协议与业务处理保持不变。
