# 好友独立聊天背景设计

## 目标

在好友聊天页面中允许用户为每个好友单独设置聊天背景图片。背景只覆盖消息滚动区域，不影响顶部好友信息栏和底部输入区域。

背景配置必须按当前登录账号和好友 ID 隔离，并由应用持久保存。退出并重新启动 App 后继续生效；只有用户主动选择新图片或执行“恢复空白背景”时才改变。

## 交互

复用 `ChatDetailView` 顶部菜单中现有的“更改聊天背景”入口，将其调整为包含以下操作的子菜单：

- “选择图片”：打开 macOS 图片文件选择器，只允许选择受支持的图片类型。
- “恢复空白背景”：删除当前账号与当前好友对应的背景；没有自定义背景时禁用该操作。

选择图片成功后立即刷新当前消息区域。用户切换好友时加载该好友自己的背景，不复用其他好友的配置。

## 存储模型

新增独立的 `ChatBackgroundStore`，负责导入、读取、替换和删除背景，不让文件系统逻辑继续堆积在 `MainChatStorage.swift` 中。

存储位置使用用户的 Application Support 目录，按以下层级隔离：

```text
Application Support/<bundle-id>/ChatBackgrounds/<account-id>/<friend-id>/background.jpg
```

规则如下：

- 图片导入后复制并标准化到应用管理目录，不依赖原文件路径或安全书签。
- 同一好友始终使用确定性目标路径；更换背景使用临时文件写入后原子替换，避免中途失败破坏旧背景。
- 原图被移动或删除不影响已设置背景。
- `UserDefaults` 不保存图片二进制数据。
- 当前账号 ID 不可用时拒绝保存并显示错误，避免不同账号共用未归属文件。

## 图片处理与显示

导入时先验证文件能被 `NSImage` 解码。图片长边超过 `3840` 像素时按原始宽高比缩小，不放大小图；随后以 `0.88` JPEG 质量编码，避免超大原图导致持久占用和聊天页解码压力。

消息区域使用 `Image(nsImage:)`、`resizable()` 和 `scaledToFill()` 等比例填满可用区域，超出部分裁剪，不拉伸变形。背景层固定在消息列表后方，消息列表本身保持透明；顶部栏和输入区域继续使用当前材质与颜色。

没有自定义背景、文件缺失或图片损坏时，回退到现有的默认空白消息背景。损坏文件不会阻断聊天操作。

## 状态与数据流

`ChatDetailView` 持有当前背景图片、是否存在自定义背景、选择器错误等轻量视图状态。

1. 页面出现或好友 ID 变化时，使用当前账号 ID 与好友 ID 从 `ChatBackgroundStore` 加载。
2. 用户选择图片后，Store 在后台完成解码、缩放和原子写入，随后回到主线程更新视图。
3. 用户恢复空白背景后，Store 删除目标文件并清空当前视图状态。
4. 加载或导入失败时保留原背景并显示简短错误提示；删除失败时同样不伪装成已清空。

## 边界

- 仅修改 macOS 客户端，不新增服务端协议或数据库字段。
- 背景不上传、不跨设备同步，也不发送给好友。
- 不改变聊天记录、附件、头像、主题或消息气泡的数据结构。
- 本次不提供背景模糊、透明度、位置拖拽、缩放调节或预设图库。

## 测试与验证

单元测试覆盖：

- 同账号下不同好友使用不同存储路径。
- 不同账号下同一好友 ID 使用不同存储路径。
- 导入后即使删除原始图片，背景仍可重新加载。
- 更换背景覆盖当前好友旧图片，不影响其他好友。
- 恢复空白背景只删除当前账号与好友的文件。
- 无效图片导入失败并保留已有背景。
- 文件缺失或损坏时安全回退为空白背景。

实现遵循先失败测试、后最小实现、再回归验证的顺序。最终运行相关单元测试和 macOS Release 构建，并确认仓库未残留构建缓存。
