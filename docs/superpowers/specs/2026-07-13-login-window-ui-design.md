# chat-storage 登录窗口 UI 改造设计

## 1. 背景

当前登录窗口采用单列纵向布局，使用系统用户头像和默认输入框样式。页面存在以下问题：

- 深浅色模式下部分文字对比度不足。
- 页面留白松散，视觉重心不明确。
- 登录入口、注册入口、服务器状态和配置入口缺少统一层级。
- 视觉语言与应用主界面的 Telegram 风格不一致。
- 错误信息存在重复展示。
- 用户名和密码在源码中预置测试值，不适合作为正式登录体验。

本次改造只调整 macOS 登录窗口的展示和局部交互，不改变认证服务、Socket 协议、注册流程或服务器配置逻辑。

## 2. 设计目标

采用已确认的“macOS 工作台式”双区方案：

- 左侧建立产品识别，展示品牌说明和服务器连接状态。
- 右侧集中承载账号输入、密码输入、登录操作及辅助入口。
- 密码框与登录按钮保持清晰的独立间距，不能紧贴。
- 所有内容在固定登录窗体内完整展示，不出现遮挡、裁切或依赖滚动。
- 兼容 macOS 明暗外观，保证文字和控件对比度。
- 保留现有业务行为和交互协议。

## 3. 窗口与布局

### 3.1 窗口尺寸

登录窗口由当前的 `500 × 550` 调整为横向约 `720 × 456`。

窗口继续采用固定内容尺寸，由 `AppWindowLayout` 和现有窗口配置方法统一控制。页面内部不使用滚动容器，左右区域必须在该尺寸内完整呈现。

### 3.2 左侧品牌区

左侧约占窗口宽度的 40%，使用稳定的深色背景，不使用渐变或大面积装饰图片。

内容包括：

- 由字母 `D` 构成的简洁品牌标记。
- 产品名称“毒药网盘”。
- 主文案“让聊天与文件，始终触手可及。”
- 一行简短说明，描述聊天、消息和私人云盘能力。
- 底部服务器连接状态。

连接状态使用小尺寸状态圆点和文本展示：连接成功为绿色，其他状态使用中性灰色或提示色。服务器地址不在左侧持续展示，详细地址放到服务器设置入口中查看，避免品牌区信息拥挤。

背景可以使用低对比度同心圆线条作为轻量装饰，但不得影响文字可读性。

### 3.3 右侧登录区

右侧约占窗口宽度的 60%，使用系统背景色，表单最大宽度约 300pt，并在区域内垂直居中。

内容顺序为：

1. 标题“欢迎回来”。
2. 辅助说明“请输入账号信息继续使用”。
3. 账号标签和输入框。
4. 密码标签和输入框。
5. 页面内错误提示。
6. 登录按钮。
7. 底部“服务器设置”和“创建账号”入口。

输入框之间保持约 14 至 16pt 间距。密码输入区域与登录按钮之间保留至少 18pt 的独立间距；出现错误提示时，通过预留错误区域吸收高度变化，不能把按钮挤出窗体。

## 4. 控件与状态

### 4.1 账号输入

- 使用人物 SF Symbol 作为前导图标。
- 占位文案为“手机号或用户名”。
- 不再预置测试账号。
- 保留回车提交行为：密码已有内容时可发起登录。

### 4.2 密码输入

- 使用锁形 SF Symbol 作为前导图标。
- 增加密码显示与隐藏按钮，使用 `eye` / `eye.slash` SF Symbol。
- 显示状态使用普通 `TextField`，隐藏状态使用 `SecureField`，二者绑定同一份密码状态。
- 不再预置测试密码。
- 回车继续触发现有 `handleLogin()`。

### 4.3 登录按钮

- 使用 Telegram 风格蓝色作为主操作色。
- 正常状态显示“登录”。
- 登录中显示小型进度指示和“正在登录…”，同时禁止重复提交。
- 用户名或密码为空时保持禁用。
- 按钮高度固定，加载状态不能引发布局位移。

### 4.4 错误提示

- 删除当前页面中重复的错误文本，只保留表单内一处。
- 错误区域预留单行高度，短错误直接显示，长错误最多显示两行。
- 使用系统红色和警告图标，兼容明暗模式。
- 输入重新编辑或再次提交时，沿用现有逻辑清理旧错误。

### 4.5 辅助入口

- “服务器设置”位于表单底部左侧，继续打开 `ConfigServerView` sheet。
- “还没有账号？创建账号”位于表单底部右侧，继续切换到 `RegisterView`。
- 两项使用文本按钮，不抢夺主登录按钮的视觉层级。

## 5. 自适应和可访问性

- 右侧背景、正文、次级文字和输入框边界使用语义化系统颜色，适配明暗模式。
- 左侧深色品牌区保持稳定，文字使用高对比度白色和浅灰色。
- 所有文本禁止使用按视口宽度连续缩放的实现；使用固定字号和明确的布局约束。
- 文字在可用宽度不足时合理换行，不能覆盖相邻控件。
- 图标按钮提供可访问性标签，例如“显示密码”和“隐藏密码”。
- 键盘焦点顺序保持账号、密码、登录，回车提交行为完整保留。

## 6. 代码组织

本次主要修改：

- `chat-storage/LoginView.swift`
- `chat-storage/chat_storageApp.swift`

`LoginView` 继续使用现有环境对象和绑定。页面按以下私有视图区块拆分，避免继续把所有 SwiftUI 层级堆在 `body` 中：

- `brandPanel`
- `loginForm`
- `credentialField` 或等价的局部输入组件
- `loginButton`
- `formFooter`

业务方法 `handleLogin()` 保持认证调用和错误映射逻辑不变，只调整与 UI 状态直接相关的处理。

## 7. 不在本次范围内

- 不修改登录请求帧、响应结构或服务端协议。
- 不修改 `AuthenticationService.login()`。
- 不改造注册页 UI。
- 不改造服务器配置页 UI。
- 不增加记住密码、自动登录或账号历史。
- 不增加新的图片资源或网络资源。

## 8. 验收标准

- 登录窗口以横向双区布局展示，品牌区和表单区层次清晰。
- 登录按钮下方的服务器设置和注册入口在窗体内完整可见。
- 密码框与登录按钮之间存在明显间距。
- 错误提示出现后不遮挡按钮或底部入口。
- 空输入、格式错误、登录中、登录失败和登录成功状态均正常。
- 回车提交、注册切换、服务器配置 sheet 和连接状态展示正常。
- 明暗模式下标题、正文、输入内容、占位文字和错误提示均可读。
- 项目能够通过现有 macOS Debug 构建。
