## 网盘视频缩略图的生成原理

### 整体流程

```
用户上传视频
     ↓
对象存储（OSS/S3）接收文件
     ↓
触发异步任务（消息队列）
     ↓
视频处理服务抽帧 → 生成缩略图
     ↓
缩略图存 CDN，URL 写数据库
     ↓
前端展示
```

---

### 第一步：抽帧

核心工具是 **FFmpeg**，几乎所有平台底层都用它（或其 SDK 封装）。

**最简单的做法——取固定时间点的帧：**
```bash
# 取第 3 秒的画面
ffmpeg -ss 3 -i input.mp4 -frames:v 1 -q:v 2 thumb.jpg
```

`-ss` 放在 `-i` 前面是为了快速 seek，不会从头解码。

**更聪明的做法——取第一个关键帧（I帧）：**
```bash
ffmpeg -i input.mp4 -vf "select=eq(pict_type\,I)" -frames:v 1 thumb.jpg
```

关键帧是完整画面，解码成本最低，且大概率是场景切换点（内容清晰）。

---

### 第二步：moov 位置的影响

这里和上面的话题就联系起来了：

| moov 位置 | 抽帧行为 |
|---|---|
| **头部** | 读取 moov → 直接 seek 到目标帧偏移 → 只读那几个 GOP 的数据，**极快** |
| **尾部** | 必须先把整个文件读完/下载完才能获得 moov → **慢，或需要整文件** |

所以大厂的视频处理管线通常会：
1. 上传完成后先做一次 **faststart 转换**（moov 挪头部）
2. 再进行抽帧、转码等后续处理

百度网盘、阿里云盘等在上传时如果检测到 moov 在尾部，会在服务端做这步 rewrite。

---

### 第三步：聪明帧选择策略

纯取固定秒数容易命中黑屏、开场白屏。大厂会做一些优化：

**跳过片头黑屏：**
```bash
# 检测非黑帧，取第一个亮度超过阈值的帧
ffmpeg -i input.mp4 -vf "blackdetect=d=0:pic_th=0.1,select='not(between(t,0,black_end))',..." 
```

**多帧采样取最佳：**
- 在 10%、30%、50% 时间点各取一帧
- 用图像质量算法（拉普拉斯方差检测清晰度）选最清晰的那张

**AI 内容理解（头部大厂）：**
- 用图像分类模型过滤掉人脸模糊、大面积黑色、文字画面等
- 优先选"画面丰富、主体清晰"的帧

---

### 第四步：工程架构

```
上传完成
  → 发 MQ 消息（视频路径、文件ID）
    → 视频处理 Worker 消费（水平扩展）
      → FFmpeg 抽帧（直接读 OSS Stream，不全量下载）
        → 缩略图压缩（WebP，比 JPEG 小 30%）
          → 上传 CDN
            → 写 DB（file_id → thumb_url）
```

关键优化点：**FFmpeg 支持直接读 HTTP URL**，Worker 不需要把视频全部下载到本地：

```bash
ffmpeg -ss 3 -i "https://oss.example.com/video/xxx.mp4" -frames:v 1 thumb.jpg
```

配合 moov 在头部，OSS 只需要传输前几百 KB 就够了，Worker 的带宽消耗极小。

---

### 一句话总结各层职责

| 层 | 做什么 |
|---|---|
| **FFmpeg** | 实际解码、抽帧 |
| **moov 位置** | 决定抽帧需要读多少数据 |
| **MQ + Worker** | 异步解耦，支持高并发上传 |
| **帧选择策略** | 保证缩略图内容质量 |
| **CDN** | 缩略图的高速分发 |
